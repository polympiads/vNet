Configuration¶

An event is described by four kinds of files. Each has a reference page; this page says which program reads which file and how a change reaches the machines.

You rarely write them by hand: vnet-roster generates all of them from one roster file (Roster and vnet-roster).

One access list for the whole network¶

Every switch must apply the same access list, or a pair of machines would be allowed on one switch and refused on another. There are two ways to get there.

Pushed by the conductor (recommended)

Set VNET_CONFIG_PATH on the conductor. The conductor sends the file to every switch as it registers, before any token or route, and again after every reload. A switch without a file of its own waits for it and refuses agents until it arrives. This is what vnet-roster sets up.

Read by each switch

Leave VNET_CONFIG_PATH unset on the conductor and set it on every switch, pointing to identical copies. The conductor compares the switches’ fingerprints and refuses a switch whose file differs from the switches already registered (VNET_CONFIG_HASH_CHECK=0 turns the check off).

A config pushed by the conductor replaces a switch’s own file, whichever the switch started with.

Fingerprints¶

The fingerprint of a config is a SHA-256 of its parsed content in a fixed order, shown as its first 12 hex digits in the logs. Two files that mean the same have the same fingerprint, however they are ordered or commented. Every switch reports the fingerprint it applies; the conductor logs a switch that runs another one.
